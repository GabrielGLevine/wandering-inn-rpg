## Design goal

Complete the six remaining board issues at the full quality bar while
minimizing top-model (Fable) and total usage. Prior estimate for these
six: ~1.5–2 session windows. Target: ≤1.5 windows, Fable share ≤20%.

## The four usage levers (all doctrine-compatible)

1. **One user-decision packet, one round-trip.** #412 keep/cut/move
   table + #413 grant/level/passive proposal + #404 lockpick name all
   land in a single decision doc. Four gates become one sitting.
2. **One composed windowed pass.** The #414 steel-thread run at close
   IS the composed eye-read for #400 (floors/night), #403 (pockets on
   route), #413 (overlay visible on route). Replaces per-issue machine
   playtests. Per-issue windowed evidence shrinks to targeted
   before/after crops only where a reviewer needs them.
3. **Implementation fully delegated.** Opus lanes (Codex if its window
   is back — pool read EMPTY 2026-08-08; re-check
   `scripts/usage_status.sh` at dispatch). Fable does: Phase-0 design,
   lane briefs, review adjudication, merge-train close.
4. **Review scaled to risk, not uniform dual-lens.** Data-only lanes
   get ONE adversarial reviewer with method hints. Engine-touching
   surfaces (#413 overlay render, #400 world.gd separation rule,
   night-mood schema) get the trace focus in that same review. The
   whole-branch composed review at train close stays (it catches a
   ship-blocker every milestone — not negotiable).

delegation — not from thinner verification.
