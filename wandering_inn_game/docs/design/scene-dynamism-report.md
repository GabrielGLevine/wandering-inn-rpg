# Scene dynamism report

Generated by `tools/scene_dynamism.gd` (issue #73). Deterministic: re-running
with no data changes regenerates this file byte-identical (stable sort by
composite desc / name asc, no timestamps). Report + soft floor, NOT a CI gate.

## Usage

Score every new/edited map with the command below before calling a scene done.
New scenes should target composite >=50; the component breakdown tells you WHAT
to add -- low internal variety (c1) means pull decor from more than one
asset-pack family, not just more decor from the same one; low composition (c3)
means add an off-center focal light/prop and dress the border band, not just
the dead center; low cross-scene distinctiveness (c2) means the biome/sprite
picks read like a different region entirely (the brothers_parlor pre-#49
smell: it borrowed the inn's exact floor tile) or share too little visual
language with the scene's own region siblings. Scores under 30 print a loud
advisory below -- treat that as a near-certain brown box and fix before
spending a windowed screenshot on it.

```
godot --headless --path wandering_inn_game --script res://tools/scene_dynamism.gd
```

## What this metric cannot see

No pixel/palette analysis -- visual harmony is proxied via asset-pack
families + mood-grade buckets, so the score is blind to actual color/pixel
clash inside a family. Combat arenas (data/arenas.json) are out of scope.
A scene in a SINGLETON region group (currently garden_sanctuary; any unknown
future map by default) gets a flat 0.85 CREDIT on the in-region half of c2
because there are no siblings to measure against -- garden_sanctuary's
upper-half calibration placement depends on that grouping decision (in the
'interiors' group it would rank mid-table). The windowed screenshot read
stays the final authority; this tool only catches the brown-box class early.

## Weights (30/25/25/10/10, per the spec's own starting split -- unchanged;
only each component's internal formula was tuned to satisfy calibration)

| # | Component | Weight |
|---|---|---|
| 1 | Internal variety | 30 |
| 2 | Cross-scene distinctiveness | 25 |
| 3 | Composition best-practices | 25 |
| 4 | Asset utilization (per-scene: novelty only) | 10 |
| 5 | Clutter penalty (subtractive) | 10 |

Full formula + rationale for each sub-signal: `tools/scene_dynamism.gd`'s own
header comment (single source of truth -- not duplicated here).

## Repo-level asset catalog utilization (component 4's non-per-scene half)

15/28 catalog packs (docs/asset-index.json) have a plausibly-matched family in
use somewhere in the repo (54%). Fuzzy name-token match, not a structured
manifest -- packs with no match are very likely PixelLab-owned/bespoke rigs
that were never meant to show up here (uncounted, not a gap).
